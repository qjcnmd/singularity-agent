# Singularity 宪章

本文记录产品方向、优先级和边界。具体功能以当前明确需求为准，实现现状见 [架构图谱](singularity.md)，仓库工作方式见 [项目指令](../AGENTS.md)。

## 产品定位

Singularity 是本地 Rust Coding Agent，以浏览器工作台为日常交互入口。`--json` 通过同一 Agent 能力提供单次评估入口，评估器负责超时与进程终止。

产品服务日常编码工作，也用于探索和评估 Agent 机制。当前以日常使用的可靠性为先；实验有明确用途和可观察效果后再进入日常工作流。

## 产品原则

- 用户确认的目标和使用需求决定产品行为。参考实现、旧文档和已有代码提供证据，不替代用户决定。
- Agent 能理解项目、读取和修改文件、执行命令、维持任务上下文、接受执行中输入，并清楚呈现结果与失败。
- 各入口共享执行能力与持久会话事实。运行、恢复和界面展示保持一致，按下述寿命约定保护历史和未完成输入。
- 结构与功能复杂度应对应实际用途。共同规则有明确归属，有必要的差异和独立状态可以保留。

## 运行边界

产品只支持 Windows，按单用户、单工作台页面使用。同一数据目录只运行一个程序，程序内支持多任务并行。

不同数据目录可分别运行程序，服务隔离评测；不支持两个程序共同读写同一历史，也不支持运行期间手动修改或导入会话文件。单页面使用不要求跨标签草稿／设置同步，也不需要页面独占租约。线程间互斥、重连水位和已支持操作的数据完整性保护仍按实际用途保留。

Agent 在本机进程中执行并维护会话；浏览器负责呈现和传递用户操作。关闭或刷新页面不应自动停止后台任务。队列和插话仅保留在当前进程内；重启后保留已保存的历史，由用户手动继续。

本地工作台能够操作文件和命令，因此保留本地监听、Host 与来源校验；单人本机使用直接打开工作台，不设置浏览器登录状态。项目登记用于组织工作上下文，不等同于文件或命令沙箱。

当前维持一套完整的 Web 交互入口。远程访问、云端执行、多用户或额外交互客户端属于新的产品范围，需要结合用途、权限和维护成本另行确定。

## 能力与维护取舍

- 多任务并行与同一任务内并行读取／搜索均属日常能力；保留全部排队、插话、编辑、撤回、提前发送和停止操作，具体行为见[工作台交互](workbench.md)。
- 保留多提供方、Chat Completions 与 Responses 两种协议，以及 models.dev 元数据补全。配置与密钥分文件保存，保留部分保存失败的明确反馈，不扩展为跨进程配置协调。
- 保留手动／自动压缩，以及先裁剪旧工具输出、必要时再摘要的机制；原始历史不随上下文缩减删除。AGENTS.md 在每轮任务开始和压缩后读取，执行中修改到下一轮生效。Skills 保留模型按需调用和手动入口。
- 轨迹保留系统提示词及变化、工具定义、回答、工具输入输出、请求选项、错误和用量，不记录或提供每次请求完整上下文的额外副本。显示规则见[工作台交互](workbench.md)。
- 只维护当前会话格式，不默认增加旧格式迁移或长期兼容。已有用户数据的迁移或删除单独确认；一次清理授权不适用于未来数据。
- 保留自动生成 Windows 下载包与校验和，不维护证书签名、SBOM 或来源证明材料。CI 的执行平台按检查用途选择，不因此增加产品平台支持。
