# Singularity 宪章

本文档约定 Singularity 的产品定位、设计原则与运行边界。
完整运行流程见[架构图](../architecture.html)，模块职责与状态归属见[架构说明](architecture.md)，工作台交互规范见[工作台交互](desktop-ui.md)，本地调试指南见[开发指南](development.md)。

---

## 1. 产品定位与目标

- **定位**：Singularity 是个人开发阶段的本地 Coding Agent，由 Rust 运行时和 Electron 桌面工作台组成。
- **桌面工作台**：支持对话、文件读取、命令执行、工具调用和会话历史。
- **直接实现当前需求**：开发阶段直接更新内部接口和保存格式，不增加迁移或兼容层。

---

## 2. 核心设计原则

1. **真实事实驱动**：时间线展示、Token 用量都来自落盘事实，不伪造、不静默吞并。
2. **渐进式上下文与保护**：压缩采用追加式摘要，历史消息永久落盘，可随时回溯完整对话过程。
3. **安全透明的本地交互**：
   - 继承系统权限执行；不监听端口，外发连接只到用户配置的模型与 MCP 服务。
   - 子进程树由系统 Job Object 管理，异常或停止时整树回收。
4. **精简架构**：模块边界清楚，不加非必要的间接层与抽象；代码以维护者能看懂、能验证为准。

---

## 3. 运行边界

- **运行平台**：仅 Windows (x86-64) 桌面。
- **实例与存储**：
  - 同一数据目录（默认 `~/.singularity`）只允许一个实例运行，避免并发写入冲突。
  - 环境变量 `SINGULARITY_HOME` 可指定独立数据目录，用于隔离调试或自动化任务。
- **通信模式**：渲染进程与 Rust 后端之间走私有 stdio 管道传输 RPC，不开放 HTTP / WebSocket 端口。
