# Singularity 宪章

本文记录产品方向、优先级和运行边界。具体功能以当前明确需求为准；技术取舍由对应 ADR 维护，实现现状见[架构图谱](architecture.md)，开发与验证规则见[项目指令](../AGENTS.md)。

## 产品定位

Singularity 是本地 Rust Coding Agent，以 Electron 桌面工作台为日常交互入口。`--json` 通过同一 Agent 能力提供单次评估入口，评估器负责超时与进程终止。

产品服务日常编码工作，也用于探索和评估 Agent 机制。当前以日常使用的可靠性为先；实验有明确用途和可观察效果后再进入日常工作流。

## 产品原则

- 用户确认的目标和使用需求决定产品行为。其他项目的实现、旧文档和已有代码只能作为证据，不替代用户决定。
- Agent 能理解项目、搜索、读取和修改文件、处理图片、执行命令、维持任务上下文、接受执行中输入和停止，并清楚呈现结果与失败。保留 Skills 的模型按需调用和手动入口、交互入口的提问能力，以及各入口共享的 MCP 工具能力。
- 各入口共享执行能力与持久会话事实。运行、恢复和界面展示保持一致，按下述寿命约定保护历史和未完成输入。
- 结构与功能复杂度应对应实际用途。共同规则有明确归属，有必要的差异和独立状态可以保留。

## 运行边界

产品只支持 Windows，按单用户、单工作台页面使用。同一数据目录只运行一个程序，程序内支持多任务并行。工作台使用 Electron 自带的 Chromium 渲染现有 React 界面。

不同数据目录可分别运行程序，服务隔离评测。会话文件由本程序创建、追加和恢复；同一数据目录内的会话写入由进程统一管理。单页面使用不要求跨标签草稿／设置同步，也不需要页面独占租约。线程间互斥、重连水位和已支持操作的数据完整性保护仍按实际用途保留。

Agent 在本机进程中执行并维护会话；Electron 渲染进程负责呈现和传递用户操作。关闭窗口隐藏到托盘，刷新窗口保留后台任务；从托盘退出时取消任务并关闭后端。未消费的引导输入仅保留在当前进程内；重启后保留已保存的历史，由用户手动继续。

本地工作台通过隔离 preload 与 Electron 主进程通信，再由私有 stdio 管道连接 Rust AppServer；不监听本地 HTTP / WebSocket 端口。主进程只接受自有工作台主 frame 的 IPC。项目登记用于组织工作上下文，不等同于文件或命令沙箱。

当前维持一套完整的桌面交互入口。远程访问、云端执行、多用户或额外交互客户端属于新的产品范围，需要结合用途、权限和维护成本另行确定。

## 数据与交付边界

- 原始历史不随模型上下文缩减删除，运行反馈与轨迹来自实际执行和持久事实。
- 只维护当前会话格式，不默认增加旧格式迁移或长期兼容。已有用户数据的迁移或删除单独确认；一次清理授权不适用于未来数据。
- 保留自动生成 Windows 下载包与校验和，不维护证书签名、SBOM 或来源证明材料。CI 的执行平台按检查用途选择，不因此增加产品平台支持。
