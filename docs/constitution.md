# Singularity 宪章

本文档阐明 Singularity 的产品定位、设计原则与系统运行边界。
完整运行流程见[架构图](../architecture.html)，模块职责与状态归属见[架构说明](architecture.md)，工作台交互规范见[工作台交互](desktop-ui.md)，本地调试指南见[开发指南](development.md)。

---

## 1. 产品定位与目标

- **定位**：Singularity 是专为本地开发者打造的专业级 Coding Agent，以高性能 Rust 原生运行时为核心，提供流畅直观的 Electron 桌面交互工作台。
- **双模运行**：
  - **日常桌面模式**：以多任务工作台为核心，提供对话、文件操作、命令执行、工具调用与上下文透明可视化。
  - **无交互评测模式 (`--json`)**：复用同一套 Agent 执行核心，通过标准 JSONL 输出供自动化评测框架与流水线调用。
- **可靠性优先**：追求在真实工程场景下的执行正确性、状态透明度与数据韧性。

---

## 2. 核心设计原则

1. **真实事实驱动**：所有时间线展示、Token 用量与执行轨迹均基于真实落盘事实，不做虚假降级或静默吞并。
2. **渐进式上下文与保护**：模型上下文压缩采用追加式摘要，历史消息永久落盘保留；支持随时回溯完整对话演化过程。
3. **安全透明的本地交互**：
   - 依赖系统原生权限执行，严格避免外部端口监听与不可信网络调用。
   - 进程树依托系统级 Job Object 管理，确保异常或停止时干净回收子进程。
4. **精简高效的高内聚架构**：模块边界清晰，消除非必要的间接层与过度抽象，以维护者可理解、易验证的代码质量为准则。

---

## 3. 运行边界

- **运行平台**：当前专注支持 Windows (x86-64) 桌面环境。
- **实例与存储**：
  - 单一数据目录（默认 `~/.singularity`）保证进程级单实例运行，避免并发文件写入竞争。
  - 支持通过环境变量指定独立数据目录以实现隔离调试或评测。
- **通信模式**：工作台前端渲染进程与 Rust 后端通过私有 stdio 管道传输 RPC，不开放 HTTP / WebSocket 端口。
