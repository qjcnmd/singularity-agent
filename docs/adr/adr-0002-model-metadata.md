# 模型智能配置与字段覆盖

日期：2026-09-26。状态：已采用。

模型 ID、提供方地址与 API 协议共同确定推荐配置。推荐资料来自提供方 `/models` 与 models.dev，提供方响应优先；公共目录只按实际端点与精确模型 ID 补充缺失字段。未取得的必填参数由用户在表单中填写。

添加与编辑共用一个模型配置表单。智能获取与用户输入共同形成最终配置；保存时必须有有效的上下文窗口和最大输出容量，未知能力不凭空添加。表单标题和操作固定，仅正文滚动。基础区展示身份、容量；高级区展示选填名称与思考选项。协议在提供方统一设置和持久化，模型沿用该协议。

每个模型保存取值和 `automatic_fields`。集合内字段在再次获取时可更新，集合外字段保留用户覆盖；旧配置已有值按手动值保留，缺失值可获取补齐。思考选项与默认档位作为同一覆盖单元。编辑一个字段只移除该字段的智能归属；重置表单清除覆盖。

用户输入模型 ID 后点击“智能配置”，结果先填入表单，保存后才影响任务。请求期间换模型或关闭弹窗时，迟到结果不再更新草稿。获取失败保留当前输入。关闭应用取消网络查询，已接受的写操作完成后再取消任务。

执行仍只读取已保存的配置，每轮冻结模型快照；后续配置变更不会修改在途轮次。已保存的值使断网后仍可使用已配置模型；公共目录只临时加载，不常驻整个目录。字段归属使用协议定义的枚举，客户端字段列表由 Rust 生成。

采用统一表单、智能归属、字段覆盖和最终配置校验；配置保存在现有配置文件与 AppServer 中，不引入模板、规则表达式或独立远端发布系统。提供方目录和 models.dev 的资料在用户请求时获取。
