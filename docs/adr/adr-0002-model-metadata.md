# 模型智能配置与字段覆盖

日期：2026-09-26。状态：已采用。

模型 ID、提供方地址与 API 协议共同确定推荐配置。许多兼容端点的 `/models` 只列出 ID，因此发现过程按提供方响应、已核实的官方端点规则、models.dev 的顺序补齐信息。目录优先精确匹配实际端点；原厂同名模型只补充容量、模态等能力，不推定其他网关的思考参数。

添加与编辑共用一个模型配置表单。智能获取与用户输入共同形成最终配置；保存时必须有有效的上下文窗口和最大输出容量，未知能力不凭空添加。表单标题和操作固定，仅正文滚动。基础区展示身份、容量；高级区展示选填名称、模态勾选与思考选项。协议在提供方统一设置和持久化，模型沿用该协议。

每个模型保存取值和 `automatic_fields`。集合内字段在再次获取时可更新，集合外字段保留用户覆盖；旧配置已有值按手动值保留，缺失值可获取补齐。思考选项与默认档位作为同一覆盖单元。编辑一个字段只移除该字段的智能归属；重置表单清除覆盖。

用户输入模型 ID 后点击“智能配置”，结果先填入表单，保存后才影响任务。请求期间换模型或关闭弹窗时，迟到结果不再更新草稿。获取失败保留当前输入。关闭应用取消网络查询，已接受的写操作完成后再取消任务。

执行仍只读取已保存的配置，每轮冻结模型快照；后续配置变更不会修改在途轮次。已保存的值使断网后仍可使用已配置模型；公共目录只临时加载，不常驻整个目录。字段归属使用协议定义的枚举，客户端字段列表由 Rust 生成。

参考 [ZCode 桌面配置草稿](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/ui/src/settings/model-provider-section/useProviderModelDraft.ts)及 [配置投影与覆盖](https://github.com/zai-org/ZCode/blob/29628c9acdb81b703bbd4080c207a0e7ce5e276e/packages/ui/src/settings/model-provider-section/ProviderModelDraftState.ts)。采用统一表单、智能归属、字段覆盖和最终配置校验；Singularity 使用现有配置文件与 AppServer，不引入模板、规则表达式或独立远端发布系统。端点规则随应用版本更新，提供方目录和 models.dev 的资料在用户请求时获取。
