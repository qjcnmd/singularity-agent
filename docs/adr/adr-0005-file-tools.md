# 文件操作工具边界

日期：2026-10-06。状态：已采用。

内建工具保留 `read` 与 `bash`。`read` 提供有界文本读取、源行范围、图片输入及 Skill 正文读取；搜索、文本编辑和文件写入通过 `bash` 调用 `rg`、Python 等本机命令完成。交互提问仍只在交互宿主启用，MCP 沿用发现、注册和执行流程。

工具名单、模型 schema、参数预检和派发由同一个 `ToolRegistrySnapshot` 维护。删除 `edit`、`write`、`grep`、`glob` 及其专用匹配、遍历、路径锁、工作区原子写入及工具 diff 的生成、解析与展示，不另建替代工具或文件操作框架。应用数据的原子写入继续服务配置、会话和图片快照。

代价是依赖本机命令环境；文件修改的权限、行尾、原子性和并发协调由具体命令负责，工作台按命令输出反馈。`bash` 仍按现有独占准入执行，保留取消、超时、进程树管理与结果先持久化后发布的顺序。

当前选择以减少工具接口和专用实现为目标。只有新的明确需求要求命令执行无法提供的文件操作或反馈，才重新评估内建文件工具。
