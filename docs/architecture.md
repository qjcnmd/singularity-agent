# 架构说明

Singularity 是面向 Windows 本地的单用户桌面 AI 编程工作台，采用 Electron 前端 + Rust `stdio` JSON-RPC 后端进程架构。源码索引见 [directory.html](../directory.html)，完整执行与数据流见 [architecture.html](../architecture.html)。

## 进程与通信

- **Electron 主进程**（[main.ts](../apps/desktop/desktop/main.ts)、[backend.ts](../apps/desktop/desktop/backend.ts)、[preload.cts](../apps/desktop/desktop/preload.cts)）：维护单实例锁，通过 `SINGULARITY_HOME` 或 `~/.singularity` 派生 Chromium `userData` 目录并持久化启动主题颜色；托管 `singularity.exe` 子进程并在 `'close'` 事件上报异常退出与完整 stderr 诊断，通过 `singularity://app/` 加载静态资源，仅在受信任主框架转发 `rpc`、`connect` 与主题写入。
- **Rust 后端**（[main.rs](../crates/app/src/main.rs)、[logging.rs](../crates/app/src/logging.rs)、[transport.rs](../crates/app/src/desktop/transport.rs)、[rpc.rs](../crates/app/src/desktop/rpc.rs)）：持有数据目录文件锁并初始化 `tracing` 滚动诊断日志（写入 `~/.singularity/logs/singularity.log`）；stdin 逐行接收 JSON-RPC 请求并派发至独立异步任务；stdout 由独立有界写入协程（`mpsc::channel(512)`）按序输出响应与 `StreamEnvelope` 事件帧，后端事件通道在非聚焦会话下过滤高频流式进度、背压（`< 512`）仅丢弃可覆写的 `ToolOutput` 与已登记 `Running` 后台快照（保留聚焦 `TextDelta` 与首次 `Running`），真饱和（`capacity <= 1`）时预留末槽发送合并 `Ready` 重同步信号；停机时先取消查询、收齐已接受 RPC 并停机全部会话，再以非阻塞 `try_send` 排空剩余事件并保留真实 stdout 写入错误，退出前调用 `runtime.shutdown_background()` 避免 stdin 阻塞导致目录锁滞留。

## 关键状态、锁序与缓存

- **MCP 连接交接**：配置锁覆盖读取配置和登记槽位，连接表的锁只覆盖内存操作。连接关闭和网络等待在锁外。退出时先等待已接收的 RPC 和会话结束，再收齐待关闭的 MCP 连接。
- **切模型预压缩**：用旧模型上次的推理档位解析客户端。档位已移除时，配置错误随本轮失败返回。
- **单向锁序**：`AppServer` 严格遵守 `lifecycle -> publication -> sessions -> 会话状态`（`view -> state`）加锁顺序，不在锁内执行磁盘全量扫描、图片解码（`UserInput::from_uploads` 移至锁外）或长耗时网络 IO；`inspect_context` 在 `lifecycle` 锁内调用 `begin_context_preview` 返回 `ContextPreview::{Skip, Busy, Run(PreviewGuard)}` 串行化并发调用（`Busy` 时通过 `Conversation::changed` 的 `wait_context_preview` 挂起等待在途预览完成后重检，`PreviewGuard` 在 `Drop` 时自动清理并唤醒）；`rewind_session` 在 `lifecycle` 锁内经 `workspace_keys_overlap` 检查同项目及父子嵌套工作区无其他在跑任务/后台命令或并发回溯并先经 `begin_rewind` 进入 `TurnLifecycle::Rewinding` 获取 `RewindGuard`，成功后再登记 `WorkspaceRewindGuard`（期间经共享 `ensure_workspace_not_rewinding` 阻止重叠工作区上的 `start`/`submit`/`compact`/`context`/`changedFiles`/`fileDiff`/`skills.list`/`context.preview`/`instructions.*`/`mcp.reconnect`/`file.read`/`remove_workspace`/`rewind`），锁外在 `spawn_blocking` 中执行 `snapshot::restore` 采集 `RestoreBackup` 后经 `commit_rewind` 返回 `RewindCommit::{Committed, PreCommitError}`（日志提交前失败时保持双守卫存活直至 `backup.rollback()` 结束并在回滚失败时记录警告且返回合并错误；日志提交落盘并发布 `SessionSettled` 后在 `spawn_blocking` 内立即释放双守卫且即便后续读取出错也不再回滚工作区）。
- **会话内存上限**：`AppServer::sessions` 使用 `SessionCache` 限制最多缓存 `16` 个空闲已打开会话，插入新会话前先按 LRU 淘汰最久未访问且 `can_evict() == true` 的旧空闲会话（防止新会话自淘汰）；`has_work()` 与 `can_evict()` 在 `auto_resume == false` 时忽略仅剩被动 `Background` 通知的队列项；重新打开时 `ConversationView` 以当前全局 `revision` 初始化事件序号。
- **统一锁外删除与停机**：`delete_session` 统一处理已打开与未打开会话：先在 `lifecycle` 锁内经 `SessionDeleteGuard::reserve` 占位 `deleting_sessions`（阻断并发打开/读/操作/删/`snapshot_target`），已打开会话同时拿 `DeleteGuard`，随即释放 `lifecycle` 锁在锁外停机运行态并在 `spawn_blocking` 中执行 `catalog.delete`（含 `snapshot::remove`），最后仅短时复加 `lifecycle` 锁移除内存会话、释放占位并发布快照。`shutdown` 通过 `JoinSet` 并发停止全部活跃会话后关闭 MCP 连接。
- **前端状态单一来源**（`apps/desktop/src/`）：`SessionStore` / `AppStore` 持有与后端 `revision` 对齐的会话、目录和流式增量状态，维护单一 `contextPreviewVersion` 计数（`modelCatalog.webSearch` 变化时在 `applySync` 自动递增，保存指令/手动刷新 Skills/变更 MCP 后由 `invalidateContextPreview()` 递增，驱动新建任务页 `ContextCapsules` 重拉 `context.preview`），会话中途收到 `ready` 原地刷新而不卸载 `<Conversation>`，启动报错后收到 `ready` 或 `app_changed` 恢复同步并清理非活跃会话陈旧 `backgroundTasks`；用户气泡右下角 `.user-meta` 聚合时间、复制与回溯编辑按钮，点击弹出 `RewindDialog`（复用 `Dialog`，查 `session.changedFiles` 可选还原文件，检测到当前会话存在未发送草稿时给出覆盖提示），并在回溯前通过 `session.imageRead` 取回历史图片还原为 `File` 附件连同原消息/文件/批注回填 `Composer` 聚焦；`RunPanel` 在 `ContextPanel`（`context === null && phase === 'idle'` 时按需请求 `session.context`，回到 `idle` 或切模型 `selection` 时重拉）下方展示 `改动文件` 卡片，点击文件行或 `ToolCard`/`EditDiff` 中的文件名链接（`edit`/`write` 打开合并差异、`read` 打开只读文件）直接进入 `FilePanel` 差异标签（`mode === 'diff'` 以保留大小写的 `diff:<sessionId>:<diffPath>` 为标签 ID 调 `session.fileDiff` 直渲 `<EditDiff>`，并在回溯、删除会话或移除工作区时刷新或关闭对应差异标签）；`McpSettings` 仅在存在 `connecting` 服务器时按 1s 轮询 `mcp.list`；左侧栏仅保留新建任务、项目/任务列表与底部「设置」入口，点击打开居中宽版双栏设置弹窗（`Settings.tsx` 聚合外观 / 模型 / 联网搜索 / 自定义指令 / Skills / MCP，模型与联网搜索共用 `ModelConfigErrorAlert` 展示不可读配置报错与重试且 `WebSearchSection` 卸载时清除保存报错，点遮罩空白处退出，Skills 在弹窗内下钻预览 `SKILL.md` 并复用 `FilePanel` 的 Markdown/源码渲染）；`DraftStore` 缓存已打开的 `IDBDatabase` 实例并按会话 key 250ms 防抖写入 IndexedDB（含未发送的助手回复文本批注，通过 `annotations.ts` 与 CSS Custom Highlight 还原高亮），在发送/删除/`pagehide` 时同步建事务刷盘；`viewPersistence.ts` 保存视图状态与全局强调色（`accentColor`，兼容读取旧 `assistantBubble`）。

## 运行边界

1. **单实例本地桌面应用**：面向 Windows 本地单用户，数据集中保存在单一 `~/.singularity`（或 `SINGULARITY_HOME`）下并加独占目录锁；不处理多实例并发写入同一数据目录，也不扩展跨平台服务端或网络接入。
2. **项目归类而非强沙箱**：工作区登记只决定 `AGENTS.md`、项目 Skills、MCP 目录键和工具默认工作目录，不对文件或命令施加额外内核级路径限制（由用户自行判断操作边界）。
3. **日志格式固定 v1**：不编写向后兼容的历史日志迁移逻辑；`0.1.0` 阶段变更日志格式时直接清理本地会话目录验证。
4. **本地直接交互模式**：不包含后台常驻守护进程、定时任务、外部 IM 网关或自动评测基础设施；扩展能力见 [已确认的取舍](decisions.md)。
