# 架构说明

Singularity 是面向 Windows 本地的单用户桌面 AI 编程工作台，采用 Electron 前端 + Rust `stdio` JSON-RPC 后端进程架构。源码索引见 [directory.html](../directory.html)，完整执行与数据流见 [architecture.html](../architecture.html)。

## 进程与通信

- **Electron 主进程**（[main.ts](../apps/desktop/desktop/main.ts)、[backend.ts](../apps/desktop/desktop/backend.ts)、[preload.cts](../apps/desktop/desktop/preload.cts)）：维护单实例锁，通过 `SINGULARITY_HOME` 或 `~/.singularity` 派生 Chromium `userData` 目录并持久化启动主题颜色；托管 `singularity.exe` 子进程并在 `'close'` 事件上报异常退出与完整 stderr 诊断，通过 `singularity://app/` 加载静态资源，仅在忽略 `#fragment` 后精确匹配 `singularity://app/` 的受信任主框架转发 `rpc`、`connect`、`setTheme` 与剪贴板权限。
- **Rust 后端**（[main.rs](../crates/app/src/main.rs)、[logging.rs](../crates/app/src/logging.rs)、[transport.rs](../crates/app/src/desktop/transport.rs)、[rpc.rs](../crates/app/src/desktop/rpc.rs)）：持有数据目录文件锁并初始化 `tracing` 滚动诊断日志（写入 `~/.singularity/logs/singularity.log`）；stdin 逐行接收 JSON-RPC 请求并派发至独立异步任务；stdout 由独立有界写入协程（`mpsc::channel(512)`）按序输出响应与 `StreamEnvelope` 事件帧，后端事件通道仅在非聚焦会话下过滤高频流式进度（`TextDelta`、`ToolOutput` 与 `Running` 后台快照），通道饱和时 `try_reserve` 失败记警告并丢弃（无分级背压与饱和 `Ready` 哨兵）；停机时先取消查询、收齐已接受 RPC 并停机全部会话，再以非阻塞 `try_send` 排空剩余事件并保留真实 stdout 写入错误，退出前调用 `runtime.shutdown_background()` 避免 stdin 阻塞导致目录锁滞留。

## 关键状态、锁序与缓存

- **MCP 连接交接**：配置锁覆盖读取配置和登记槽位，连接表的锁只覆盖内存操作。连接关闭和网络等待在锁外。退出时先等待已接收的 RPC 和会话结束，再收齐待关闭的 MCP 连接。
- **单向锁序**：`AppServer` 合并 `lifecycle`/`sessions` 为单一 `sessions` 锁，严格遵守 `app_publication -> sessions -> 会话状态`（`view -> state`）加锁顺序，不在锁内执行磁盘全量扫描、图片解码（`UserInput::from_uploads` 移至锁外）或长耗时网络 IO；执行类 RPC（`submit`/`compact`/`inspect_context`/`rewind_session`）经 `open_conversation(..., require_workspace: true)` 在打开并写入会话缓存前验证工作区已注册；`inspect_context` 简为入口短锁检查（已取消/`closing`/运行中/已缓存即跳过）→ 锁外只读发现 MCP → 发布前短锁复检同条件，仍有效才写入 `view.context` 并发布 `ContextLoaded`；`rewind_session` 不涉及工作区文件修改，先在锁外完成 `parse_session_input` 与 `app_core::load_agent_instructions` 预检，再在单会话 `Conversation::rewind` 锁内校验 `!closing && !is_busy() && !has_running_background() && !has_active_inbox()` 与 `models.validate_selection`，随后调用 `SessionManager::rewind_before_message` 按任意用户消息 ID 截断日志、重置视图并在同锁内入队启动重发回合。
- **会话内存上限**：`AppServer::sessions` 使用 `SessionCache` 限制最多缓存 `16` 个空闲已打开会话，插入新会话前先按 LRU 淘汰最久未访问且 `can_evict() == true` 的旧空闲会话（防止新会话自淘汰）；`has_work()` 与 `can_evict()` 经 `has_active_work()` 统一判定，在 `auto_resume == false` 时忽略仅剩被动 `Background` 通知的队列项；重新打开时 `ConversationView` 以当前全局 `revision` 初始化事件序号。
- **统一锁外删除与停机**：`delete_session` 统一处理已打开与未打开会话：先在 `sessions` 单锁内经 `SessionDeleteGuard::reserve` 占位 `deleting_sessions`（阻断并发打开/读/操作/删），若会话已打开同时标记 `closing`，随即释放 `sessions` 锁在锁外停机运行态并在 `spawn_blocking` 中执行 `catalog.delete`，最后仅短时复加 `sessions` 锁调用 `complete_locked` 移除内存会话与删除占位（中途报错由 `Drop` 自动回滚 `closing` 与占位），释放锁后发布快照。`shutdown` 通过 `JoinSet` 并发停止全部活跃会话后关闭 MCP 连接。
- **前端状态单一来源**（`apps/desktop/src/`）：`main.tsx` 单次调用 `appStore.start()` 启动订阅与首包同步；`SessionStore` / `AppStore` 持有与后端 `revision` 对齐的会话、目录和流式增量状态，维护单一 `contextPreviewVersion` 计数（`modelCatalog.webSearch` 变化时在 `applySync` 自动递增，保存指令/手动刷新 Skills/变更 MCP 后由 `invalidateContextPreview()` 递增，驱动新建任务页 `ContextCapsules` 重拉 `context.preview`），会话中途收到 `ready` 原地刷新而不卸载 `<Conversation>`，`bootstrapLoad.status === 'error'` 时暂停消费后续流帧，仅走页面「重试」按钮或 `Ctrl+R` 重新同步，`resetBaseline` 清理非活跃会话陈旧 `backgroundTasks`；空闲时任意用户气泡右下角 `.user-meta` 展示时间、复制与铅笔编辑按钮（运行中自动隐藏），点击直接在原气泡内展开 `<InlineMessageEditor>`（`Esc` 取消不改历史，`Enter` 或点「发送」无额外确认弹窗直接调 `appStore.editMessage` 先取回原图再以拍平必填 `session.rewind { sessionId, messageId, text, images, files, annotations }` 交由后端预检输入、指令与模型后再在同一会话锁内截断并立即启动重发，校验失败不会破坏原历史）；`RunPanel` 在 `ContextPanel`（`context === null && phase === 'idle'` 时按需请求 `session.context`，回到 `idle` 或切模型 `selection` 时重拉）下方仅展示一行紧凑的 `改动文件` 总览入口（按 `workspaceRoot` 轻量拉取文件数与总增删行，非 Git 目录自动隐藏），点击在右侧停靠栏 `FilePanel` 打开项目级专属 `changes` 标签页（生命周期跟随项目而非单个任务，监听同项目任一任务结算/变更自动刷新，多项目并行且同名时逐级补足父目录区分；带 `includeDiffs: true` 一次批量预取工作区全部差异，点击任意文件行原地 0ms 瞬开/收起 `<EditDiff>`；超 2 MiB 预算的大改动集展开时直接调 `session.fileDiff` 按需拉取）；已结束回合若含产生真实变更或新建文件（由 `write` 工具上报 `fileCreated` 标识）的 `edit`/`write` 工具修改，由 `timeline.ts` 纯工具级聚合并在回复末尾渲染 `<TurnChangesCard>`，点击文件行或「查看改动」直达右侧 `changes` 标签并自动定位展开对应文件；点击 `ToolCard`/`EditDiff` 已连接项仅展示工具数、拆分加载报错与变更报错且仅在存在 `connecting` 服务器时按 1s 轮询 `mcp.list`；左侧栏仅保留新建任务、项目/任务列表与底部「设置」入口，点击打开居中宽版双栏设置弹窗（`Settings.tsx` 聚合外观 / 模型 / 联网搜索 / 自定义指令 / Skills / MCP，模型与联网搜索共用 `ModelConfigErrorAlert`，URL/ID/档位校验收口至后端，前端仅保留容量校验、`responses`+`on` 提示与非空去重模型 ID；点遮罩空白处退出，Skills 在弹窗内下钻预览 `SKILL.md` 并复用 `FilePanel` 的 Markdown/源码渲染）；`DraftStore` 缓存已打开的 `IDBDatabase` 实例并按会话 key 250ms 防抖写入 IndexedDB（含未发送的助手回复文本批注，通过 `annotations.ts` 与 CSS Custom Highlight 还原高亮），在发送/删除/`pagehide` 时同步建事务刷盘；`viewPersistence.ts` 保存视图状态与全局强调色（`accentColor`）。

## 运行边界

1. **单实例本地桌面应用**：面向 Windows 本地单用户，数据集中保存在单一 `~/.singularity`（或 `SINGULARITY_HOME`）下并加独占目录锁；不处理多实例并发写入同一数据目录，也不扩展跨平台服务端或网络接入。
2. **项目归类而非强沙箱**：工作区登记只决定 `AGENTS.md`、项目 Skills、MCP 目录键和工具默认工作目录，不对文件或命令施加额外内核级路径限制（由用户自行判断操作边界）。
3. **日志格式固定 v1**：不编写向后兼容的历史日志迁移逻辑；`0.1.0` 阶段变更日志格式时直接清理本地会话目录验证。
4. **本地直接交互模式**：不包含后台常驻守护进程、定时任务、外部 IM 网关或自动评测基础设施；扩展能力见 [已确认的取舍](decisions.md)。
