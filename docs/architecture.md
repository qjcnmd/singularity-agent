# Singularity 架构说明

完整运行流程见根目录的 [architecture.html](../architecture.html)：所有流程和模块关系画在一张大图里，拖动画布移动，滚轮缩放；方向键和 Page Up / Page Down 移动，`+` / `-` 缩放，Home 回到起点。箭头表示顺序和分支，节点说明状态由谁维护，悬停可看源码位置。

本文记录模块职责、状态由谁维护、主要流程的规则和源码入口。已经确认保留的设计见[已确认的取舍](decisions.md)，界面细节见[工作台交互](desktop-ui.md)，调试命令见[开发指南](development.md)。

## 设计原则

- **只显示真实发生的事**：时间线、运行状态和 Token 用量都来自已保存的记录和实际执行结果，不编造，也不静默丢弃。工作台和重新打开的历史走同一套执行流程和会话日志。
- **压缩不丢历史**：压缩只追加摘要，原始消息一直保存在日志里，随时可以回看完整对话。
- **开发阶段直接改**：内部接口和保存格式直接更新，不加迁移或兼容层。

## 运行边界

- 只支持 Windows x86-64 桌面。
- 一个数据目录（默认 `~/.singularity`）只运行一个实例；`SINGULARITY_HOME` 可以指定另一个目录，给调试或自动化单独使用。
- 渲染进程和 Rust 后端只走私有 stdio 管道，不监听 HTTP / WebSocket 端口；对外只连接用户配置的模型和 MCP 服务。
- Agent 继承 `Singularity.exe` 的本机权限。项目只用于提供上下文和给任务分组，不限制文件访问范围。
- 命令和 MCP 子进程放进 Windows Job Object，停止或异常退出时整棵进程树一起回收。

工作台通过 `app` 内的会话模块调用 `agent`。`model::Message` 同时用于模型回复、日志里保存的消息和下一次请求；Chat 和 Responses 在发送时才各自编码，公开历史只取可显示的部分。

Agent 通过 `TurnEvent` 通知后端，后端再发布显示内容或运行快照；历史读取和实时事件共用 `HistoryItem` 与 `ThreadTurn`。每个条目自带运行、完成、失败或中断状态，工具另有等待执行状态，前端直接显示。当前回合中尚未开始的工具调用显示为等待；任务已结束或应用重启后，没有结果的调用显示为中断。工具调用和结果按条目 ID 合并为一项，流式正文只发送增量。回复保存后，按正文、思考和工具在消息中的实际顺序替换临时内容，后续工具进度更新原位置；重新读取历史使用同一套转换规则。


### 管理页 RPC 与回复数据

| 接口或字段 | 用途 |
| --- | --- |
| `instructions.read` | workspaceRoot 为 null 时读取全局 AGENTS.md，否则读取项目根目录 AGENTS.md；返回 path 和 content，文件不存在时正文为空 |
| `instructions.save` | 同目录唯一临时文件写入后原子替换目标；失败清理本次临时文件并返回原错误，成功直接返回目标路径和本次写入的原文；下一轮开始时生效 |
| `file.read` | 文件栏读取一个文本文件：路径可为绝对、`~/` 开头或相对任务工作目录；超过 2 MB、二进制或非 UTF-8 时返回原因 |
| `SkillMetadata.path` | 技能列表中展示实际入口路径 |
| `HistoryItem.message.at` | 消息保存时间，显示用户发送时间及助手完成时间 |
| `HistoryItem.message.stats` | 截至这条回复的会话累计用量（`SessionModelUsage`），只附在助手消息最后一段正文。读取历史时按日志顺序累计到这条消息；实时事件在 ProviderAttempt 累计后、发布 message/finished 时附上当时的累计，两者结果相同 |
| `ThreadTurn.firstTokenAt` | 历史首 token 时间；实时界面在收到第一个非空增量时记录本地时间 |

管理页由 `ManagePages.tsx` 调用现有 RPC 客户端；`SessionStore.page` 维护当前页面。打开管理页会更新选择序号，仍在提交的消息完成后不会把用户拉回会话。MCP 配置组件移到管理页，连接状态查询、编辑和操作忙碌状态由 `McpSettings.tsx` 自己维护；离页卸载时作废旧请求并停止轮询。

`TimelineItem.tsx` 用每条消息的 stats 计算平均 TTFT、平均速度、总 token 和缓存比例。后台 bash 的工具结果包含 taskId，卡片据此查对应后台任务，随命令从运行变为结束、停止或失败。阅读位置继续由 `viewportAnchors` 保存，贴底动画和展开暂停由 `Conversation.tsx` 管理。

## 状态由谁维护

| 数据或状态 | 维护者 | 规则 |
| --- | --- | --- |
| 项目路径 | `app::WorkspaceStore` | 只保存规范化目录，保留显示大小写；RPC、任务分组和界面偏好以忽略大小写的目录为键，界面从路径取文件夹名；项目分组不影响工具权限 |
| 任务运行阶段与停止 | `app::runtime::Conversation`、`TurnControls` | 会话决定能否开始新操作，单次上下文预览也计入占用并由会话持有取消信号；每个回合或独立压缩各有一份 `TurnControls`，负责提问和停止。接受停止和确定最终状态共用一把锁；操作结束或预览收尾时唤醒停止等待者 |
| 尚未保存的输入 | 会话内的 `SteeringInbox` | 首条消息和后续消息共用一个内存队列，按顺序保存；运行快照列出待处理消息，图片按需从队列读取；重启后队列不恢复 |
| 消息、工具结果、请求记录、摘要、图片 | `agent::SessionManager` 和会话图片目录 | 会话日志保存完整历史；摘要只影响之后的模型上下文，原历史保留 |
| 后台命令的查询和进程控制 | `agent::tools::BashTasks` | 界面和模型共用查询；已保存的终态从日志读取，内存只保留正在执行或收尾的命令和保存失败的结果 |
| 公开历史和任务列表 | `app::runtime::ThreadCatalog` 与 `history.rs` | 按需从会话日志解析生成 |
| 未保存的输出和最后事件序号 | `app::runtime::Conversation` | 只保存还没写入日志的正文、工具进度和压缩状态；事件序号来自 AppServer 的全局计数 |
| 会话累计用量 | `history::accumulate_request_usage` | 读取历史和实时事件用同一套累计规则；随运行快照返回，任务列表不带用量，累计保留在运行状态中，回复下方的统计是截至该条回复的同一份累计 |
| 当前上下文用量 | `history::context_usage` | 后端从日志末尾读取最近普通请求的实际输入数，配上窗口大小（打开任务时取模型配置，每轮开始后用该轮解析出的值）；成功压缩或切换模型后清除旧读数，前端据此计算占用比例 |
| 模型配置与密钥 | `model::ModelConfigManager` | 都存在 `config.json`，一次原子写入；协议在提供方上设置；对外目录隐藏密钥；每轮读取一次并解析模型选择，返回本轮使用的值 |
| 本轮加载的指令与工具名称（内置工具和 MCP 工具分开） | `ConversationView` | 加载完成时通过事件更新运行状态小面板，读取任务时补齐；普通运行状态不重复携带这些内容 |
| MCP 配置与连接 | `mcp::McpManager` | MCP 管理页和执行共用一个实例，连接按项目目录复用；配置文件和设置接口共用 `protocol::McpTransportConfig`，省略的参数、环境变量和请求头按空值处理 |
| 草稿、视图偏好、界面显示 | React 草稿存储、`AppStore`、`SessionStore` | 空白页共用一份草稿，已发送的任务按任务 ID 存草稿；历史读取和实时事件更新同一份回合列表 |

Tokio 运行时由 `main` 持有。`Conversation` 长期持有会话写者和输入队列，所有保存都经过这个写者；它只保留当前操作的临时显示条目，读取时与已保存历史合并，操作结束后清除。

普通提交、独立压缩和后台续跑在 `lifecycle.rs` 检查各自的启动条件，然后共用一次建立停止控制、占用任务和发布运行状态的步骤。`view.rs` 负责历史读取、临时显示内容和事件发布；后台命令完成通知在 `background.rs` 中触发后续回合。

## 一轮执行

空白页没有后端会话，输入区显示项目选择器；会话创建后输入区只显示附件、模型和发送控件。首次发送调用 `session.start` 创建会话并接受第一条消息，后续消息使用 `session.submit`。点击发送时确定项目、模型、草稿和当前页面，并将图片编码为 data URL；其他附件只传绝对路径。正文中只保留原始文字，不额外传递技能路径。后端接受时检查附件路径指向现有文件，保存用户消息时把路径列表追加到模型读取的正文，界面显示的原始文字放在 `display_text`，路径另存在消息的 `files` 中，用于历史里的文件卡片。首次发送只读取当前任务，返回任务摘要、运行状态和该任务的事件序号，前端直接加入列表；若发送期间没有切换页面，则直接打开新任务，读取正文的结果不影响发送结果。发送成功后清理未被继续编辑的草稿，失败则保留草稿。

`DraftStore` 首次读取 IndexedDB 失败时，以空草稿继续编辑。后续编辑照常保存，允许覆盖当前任务的旧草稿；发送后清空、删除任务和移除项目照常清理草稿。草稿读取、自动保存和清理失败都不弹提示；自动保存失败时保留内存内容，清理失败也不影响已完成的任务删除或项目移除。

技能引用以空白分隔，手动输入和候选选择都只写入 `/技能名`。`AppServer::start_session / submit` 接受输入前，由 `UserInput::from_uploads` 按当前目录解析可由用户调用的技能，按首次引用顺序去重并完整读取入口；原文后附技能名称、绝对路径、资源基准目录和全文。读取失败直接返回发送错误，首次发送不创建任务，后续发送不进入队列。输入构造一次完成校验、图片解码和技能读取，队列分别保存原文和技能追加段；Agent 消费时拼接附件路径，写入用户消息的 `content`，原文放在 `display_text`，历史恢复沿用保存内容。正文可包含多个引用，未知名称、路径和紧贴标点的词保持原文。没有技能引用时不扫描目录。技能目录只扫描直接子目录中的 `SKILL.md`，不接受根目录下平铺的 Markdown 文件；模型自动选择技能仍按目录提示用 `read` 加载。

输入检查通过后进入队列。会话空闲时立即创建本轮的 `TurnControls`，准备、执行和收尾都用它。准备阶段由 `Conversation::prepare_request_context` 解析模型、读取当前项目指令，再写入回合开始记录。Agent 随后扫描技能、发现 MCP 工具，组装本轮的指令和工具定义；同一轮的工具循环和自动压缩都复用这份定义，下一轮（包括重启后的第一轮）重新读取。全局和项目指令完整读取，不截断。

本轮加载的指令正文和工具名称保存在 `Conversation` 中供运行状态小面板查看，由加载完成事件更新，并在读取任务时返回完整内容；输入排队、停止、提问和压缩等运行状态更新不重复发送。下一轮加载后替换。重启后还没跑过回合时，工作台通过 `session.context` 让 `Conversation::inspect_context` 按回合开始时的同一套规则加载一次（指令文件、Skills 目录、MCP 工具），结果同样以 context/loaded 发布；本次启动已有上下文时直接沿用。

预览同一时刻只登记一次；新操作、模型设置更新或关闭会取消旧预览，已取消的结果不发布。RPC 将退出取消信号传入预览，等待预览清除登记后完成；停止也会等待登记清空，项目在预览期间按既有占用规则拒绝移除。每次模型请求携带本轮完整指令和工具定义；工具说明随工具定义发送，不在 Developer 指令里重复列清单，完整工具定义也不写入历史。

本轮指令和工具定义的 Token 预算在加载完成时计算一次，普通请求和摘要请求复用这个值；下一轮重新加载和计算。

内置工具直接持有 `ModelToolSchema` 和对应参数解析函数，发送给模型时复用该定义；MCP 连接与服务器描述仍由 MCP 模块维护。

Agent 按顺序保存并消费队列中的输入。准备失败时保留队列；用户停止时清空尚未消费的用户消息。回合结束后会话释放占用并检查队列：有待处理输入且允许自动继续时，创建下一轮的 `TurnControls` 并执行。新提交和回合结束共用会话的状态锁，AppServer 只转发已经构造好的事件。

启动、运行和收尾期间都接受追加输入，停止期间拒绝；准备期间也能停止。队列只负责保存，能否开始新操作由 `Conversation` 决定。组装请求前先交付已到达的输入；压缩期间收到的消息进入下一次普通请求。

回复达到输出上限时保留已生成的内容，即使只有思考或没有正文，也保留真实用量并按截断处理；回合保存失败原因并提示继续，其中没写完的工具调用只保存错误结果，不执行。Responses 的拒绝正文和普通正文走同一套增量处理。解码器在失败和取消时交回已生成的正文和思考，普通请求保存为带请求结果的助手消息；历史按请求结果显示失败或中断，这些消息不进入后续模型上下文或压缩。

## 上下文与压缩

模型上下文由 `agent::session::context` 从会话日志生成。工具结果按完成顺序保存，再按调用 ID 配对；缺失的结果补为“结果未知”，压缩切点不拆开一组工具调用。普通请求和摘要请求共用消息表示和 Token 估算。

预算优先使用当前模型最近一次普通回复的实际用量，只补算之后新增的消息。每轮首次请求、切换模型或压缩后，重新估算对话、指令和工具定义，思考文本与正文使用相同估算；不回传思考的模型可能因此稍早压缩。图片名称、尺寸和保存路径合成同一附加文本块，生成与估算共用规则；普通请求、摘要选段、压缩切点和输出余量都计入这块文本，沿用实际用量时只补算后续新增消息的说明。缺失工具结果的占位说明直接估算固定文本，并与普通消息共用消息、内容块和工具结果的开销规则。图片仍在写者锁外读取。上下文窗口和最大输出分别保存，实际请求再按窗口余量限制输出。输入已经占满窗口时，直接提示缩短输入或换用窗口更大的模型。

自动压缩在估算达到窗口的 90% 时触发，保留最近约 10% 的对话，并扩展到完整的工具调用组。手动压缩也走同一套指令和工具组装；没有更早的对话可总结时直接结束，不扫描技能也不调用模型。

独立压缩先从会话中选出需要总结的历史，没有可总结的内容时直接结束，不读取模型配置、项目指令、技能或 MCP；有选段时再准备请求。自动压缩在本轮请求上下文中选取历史。两者随后调用 `RequestContext::compact_selected`，复用选段并分配条目 ID，成功后用同一 ID 保存摘要。

独立压缩在保存摘要前关闭停止入口：此前接受的停止使本次压缩中断，开始提交后拒绝停止。自动压缩只检查本轮取消信号，后续模型和工具循环仍可停止。失败、取消或无需压缩只发布当前状态，保留原上下文。成功后，模型只读取最后一份摘要和保留的消息；自动压缩继续原任务，独立压缩处理已收到的输入。

模型明确返回上下文超限时，每次生成最多压缩并重发一次。自动压缩的错误关联到当时显示的失败条目，重新打开任务时由保存的回合错误显示原因。独立压缩失败时保留错误并暂停自动继续；取消按中断处理。

### 摘要请求与缓存

摘要请求沿用本轮普通请求的指令、工具定义和早期历史前缀。已有摘要保持原位置，末尾追加总结要求。摘要最多输出 8192 Token，同时受模型上限和窗口余量限制。实现见 [PreparedCompaction::new](../crates/agent/src/compaction.rs)。保留指令和工具定义的原因见[已确认的取舍](decisions.md#摘要请求保留指令和工具定义)。

## 工具

工具参数在注册表里检查。Bash 的命令和说明都必须是字符串，说明至少含一个字符（空格照常保留），与发给模型的定义一致；不满足时沿用工具参数错误的保存路径。最多同时运行八个工具（含 MCP）：每完成一个就保存结果、发布完成事件，再启动下一个。实时完成事件与历史读取共用 `message::public_tool_result`，从工具结果消息生成正文、图片、错误、耗时和源文件行号。提问工具先等其他工具结束，再单独执行。保存失败时不再启动剩余调用，取消并等待已启动的工具结束。

Bash 用 Tokio 异步读取 stdout 和 stderr，同时等待主进程退出、超时或取消，不用读管道线程或轮询。进度回调异步发送到有界队列，队列满时等待消费，不阻塞运行时线程。Bash 和 MCP 子进程都通过 `process-wrap` 加入 Job Object 并隐藏控制台窗口。前台命令结束（含正常退出、超时、取消或错误）时先通过 Job Object 终止整棵进程树，最多等 5 秒回收主进程，再最多用 2 秒读完剩余输出；管道超时未闭合时停止读取并附加截断提示，关闭作业句柄时终止残留后代进程。写完整输出文件的同步 IO 放在 `block_in_place` 里，不占用运行时线程。

MCP 的结果和 Bash 输出共用一套捕获：最多显示 2000 行或 50KB，接收输出时首次超限就创建临时文件保存完整文本，后续输出继续追加；读取进度和结束捕获只生成显示内容及文件位置。接收、预览和最终结果共用截断与文件说明规则；未截断的最终结果直接移交已捕获的正文，运行中预览仍保留捕获状态。保存失败只报告原因，不重试。结构化内容和文字里的同一份 JSON 只保留一次。完整输出使用系统临时目录，不按保存天数扫描或删除文件。

## 后台命令

`Conversation` 持有后台进程管理器，普通回合结束不会关闭它。`bash` 用 `yield_time_ms` 控制等待时间：默认 10 秒，允许 0～30000 毫秒；为 0 时启动成功就返回任务 ID，等到时间仍未结束就返回同一进程的 ID，不重新执行。总时限只由可选的 `timeout_ms` 指定，转到后台后沿用；不指定时一直运行到退出或被停止。

模型用 `task_list` 查看本会话的后台命令（只含 ID、命令、说明和状态），`task_output` 读取输出并对活进程有限等待，`task_stop` 停止单个命令。列表摘要与界面完整列表共用最新已保存记录、活态覆盖及历史中断的判定，摘要直接投影所需字段，不复制输出正文。重开会话后，列表和输出仍可从保存记录读取；已经结束或中断的命令不再等待，重复停止直接返回原结果。工作台运行状态小面板从同一列表筛选正在运行的后台命令，展开可看命令和输出并停止；终态仍保留在历史和前端状态中供消息区使用。界面和模型共用 `BashTasks` 的查询，不接管旧 PID。

`BashTasks` 通过会话写者保存开始和最终状态；进度只在内存中更新并发布。每次更新释放数据锁后，直接调用 `Conversation::on_background_update`，完成发布再处理该命令的下一次更新；中间没有转发队列或监听任务。任务读取与事件发布仍共用会话视图锁，旧进度不会晚于较新的命令状态发布。开始记录和进程条目一起登记，查询不会把刚启动的命令误认为历史中断。命令自然结束时，保存终态、把通知放进输入队列，再发布最终状态并释放进程条目；`Conversation` 负责启动待处理的回合。后台完成结果区分进程回收失败与日志保存失败，保存失败先暂停自动继续，再发布保留在内存中的失败任务和会话错误，界面立即结束运行显示；两种失败都保留内存条目，`task_output` 和单独停止仍报告真实原因；关闭等待只返回回收失败，已结束进程的旧保存错误不阻止删除任务。查询以最后保存的终态为准，只有仍为运行中的记录才读取实时输出；没有对应活进程的运行记录显示为中断。

回合结束和后台唤醒共用一个入口：检查空闲、允许自动继续、会话未关闭、队列非空。内部通知只带命令 ID 和状态，不伪装成用户消息。用户停止前台会暂停自动继续，后台命令继续运行；下一条用户消息恢复。单独停止后台命令不触发模型继续。停止操作只在任务不存在、进程回收或终态保存失败时报错；命令自身的非零退出码留在命令结果中。模型工具仍按命令结果判断成功或失败。

实现参考了 [Codex 的命令工具](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/unified_exec/exec_command.rs)、[会话进程管理](https://github.com/openai/codex/blob/main/codex-rs/core/src/unified_exec/process_manager.rs)和 [Claude Code 的后台命令](https://code.claude.com/docs/en/interactive-mode.md#background-bash-commands)。本项目只采用并行、任务 ID、有限等待和完成通知，不引入交互终端、远程执行或重启接管。

`bash::Process` 直接持有进程和 Windows Job Object，负责启动、读取输出、超时和回收。前台转后台时移交同一个 `Process`；结束时先终止并等待整棵进程树，再收完输出并返回结果。

## 模型请求

`OpenAiProvider::complete_stream` 在同一个协议分支里完成请求编码、选择端点和解码，续接数据使用实际请求的端点。提供方地址填 API 根，保留完整的自定义路径，再追加接口路径。SSE 切帧器接受 CR、LF、CRLF，跨数据块的 CRLF 只算一个换行；只忽略流开头的 UTF-8 BOM。

自动重试只用于网络故障、超时、限流、请求冲突和服务繁忙，最多尝试三次；未知的提供方错误直接显示。重试遵守服务端要求的最短等待，等待期间可以停止。模型请求与模型列表查询共用 HTTP 状态分类：408、409、429 和 5xx 归为暂时失败；列表查询仍由用户手动重试。响应体里有已知错误码（如上下文超限）时以错误码为准。

已经显示部分正文或思考时，符合条件的故障仍自动重试。重试前移除本次未完成的输出，保留请求记录和已上报用量，再重新生成整次回复；失败片段不进入模型上下文。等待期间任务保持运行，不单独显示重试提示。最后一次失败时保存已有正文和思考供查看，并显示错误。

模型选择在配置、RPC、草稿、运行状态和会话设置中统一用 `ModelSelection`（提供方、模型、思考档位）。空白页用全局默认值填充选择；首次发送必须带明确的模型，日志的第一条记录保存该选择。已有任务始终使用最后保存的选择，全局默认值变化不替换它。思考档位只取任务保存的选择；未选择时使用提供方默认行为。档位直接用提供方的名称，开关在协议编码时转换。Responses 按原顺序保存正文、思考和工具调用，编号、阶段、签名和加密内容跟随对应内容块。提供方私有字段只发给原来的提供方、模型、协议和地址。Chat 续接保留提供方实际返回的思考字段，包括合法的空字符串。显示思考在首个非空文本到达时固定来源；同一块中顶层思考优先，随后流式增量、成功、失败及取消后的最终文本始终使用同一来源，私有 `reasoning_details` 仍完整保留供续接。object 型 usage 在收到时直接解析为用量；无效 object 覆盖为未知，缺失或非 object 不覆盖已有值。

正常未截断回复直接检查内容块中是否有非空白正文或工具调用，并逐调用校验 ID 非空且唯一、名称非空；长度截断保留既有例外。校验不拼接整段正文，也不构造工具引用列表。

Chat 的 `on` 只适用于 `thinking_type` 和 `enable_thinking` 开关字段；默认的 `reasoning_effort` 字段和 Responses 协议使用具体档位或 `off`。模型编辑器按这条规则提供选项，保存表单和后端读取配置时也检查；已有无效选项保留供用户修正。

模型发现只返回当前提供方的模型 ID。导入只添加尚未配置的 ID，容量和思考选项由用户手动填写；已有模型的参数保持原值。切换模型 ID 时保留已填写的参数。查询失败显示 HTTP 状态及提供方有界错误正文，正文读取失败附实际读取原因；目录直接过滤、排序并去重模型 ID，不构造中间条目列表。

模型配置由 `ModelConfigManager` 读写；保存或删除成功后直接从写入的配置生成隐藏密钥的目录，`AppServer` 在发布锁内递增序号并返回该目录，修改失败直接返回原因。增删项目或删除任务成功后异步发布目录快照，读取任务列表失败不影响已保存的结果。`config.json` 的读写入口在 [config/user/mod.rs](../crates/model/src/config/user/mod.rs)。模型、MCP 和项目登记都用 `core::write_json_atomic` 写文件（缩进 JSON、末尾换行、原子替换），各自负责建目录、错误提示和写入成功后更新内存。替换文件直接使用标准库的 `std::fs::rename`，写入临时文件后仍先刷盘。

## 用量

普通回复把消息、实际用量和耗时写进同一行日志；最终失败或取消时，已有的正文和思考也按同样方式保存。需要重试的失败尝试、没有可显示内容的失败和摘要请求单独记录。重试和取消时已上报的用量也计入合计。

模型回复和请求记录共用 `protocol::ModelUsage`。每次请求结束后先保存，再更新运行快照中的累计用量和当前上下文用量；单次请求记录和模型设置保留在日志里，不转成界面历史条目。每次请求使用一条日志记录的 ID，保存回复或单独的请求结果时沿用它；重试分配新 ID，请求结果内不重复保存 ID。输入和输出计数都有效时才算有用量；总数优先用提供方上报的值，没有时取输入与输出之和。缓存计数可选；没上报不当成零，明确的零照常保存。

## 会话日志

会话文件以换行作为一行完成的标记。只读打开时忽略没有换行的末尾，写打开时截掉它；完整行解析失败仍报告实际错误。创建任务时独占新建日志，直接写入文件头和初始模型设置；读取时检查第一条记录含模型选择，后续记录可以更新选择。

历史从首条回合开始记录起分组，初始模型设置不生成空回合。回合 ID 同时用作开始记录的 ID，结束记录引用它；每个历史回合还有开始时间和状态，没有结束记录时显示中断。实时事件由回合开始事件创建回合，其余事件更新已有回合；读取历史已经包含该回合时，开始事件保留其中的内容。独立压缩显示在最近一轮内。

完整历史投影按记录顺序共享一次局部用量累计：只在首回合前初始化，随后逐回合推进，每条回复仍附截至当时的累计值，最终累计直接用于运行快照，不再重扫日志。实时消息的时间同样使用日志追加返回的保存时间，重新打开历史保持一致。

任务摘要直接逆序读取最近一条回合开始或结束记录，确定末轮状态；更新时间取最近一条非元数据记录，修改模型设置或任务名称不刷新时间。只有读取完整历史时才划分全部回合。后台命令、压缩和请求记录不改变回合划分。

图片先写入独立编号的文件，写完才在日志里保存引用；重试写入相同内容。保存、读取和删除图片共用 `agent::session::session_images_directory` 生成目录。预览已打开任务的图片时，从输入队列或当前写者的记录里查找，不重新解析整份日志；未打开的任务从文件读取。

数据文件的位置、备份和维护见[安装与配置的数据目录章节](INSTALL.md#数据目录)。

## 工作台同步

RPC 在一张方法匹配表中分发；文件读写进入阻塞工作线程，网络查询和停止等待直接异步执行。退出时取消网络查询；上下文预览沿 RPC 接收退出取消信号并完成收尾，传输层先收齐已接受的 RPC，再停止各会话。

工作台事件经单消费者队列依次写到 stdio，不丢事件。连接状态由 `RpcClient` 管理；`SessionStore` 收到就绪事件后直接读取工作台，其余事件由 `sync` 更新状态。项目和历史读取分别显示加载和错误。RPC 错误只携带错误码和实际原因，界面在操作处显示原因。应用目录快照带上各任务的当前阶段和未保存的错误，刷新页面后侧栏仍能显示准备失败或保存失败。目录读取失败直接显示原因，由用户重试。

时间线的历史行只随 `facts` 与末轮保存失败标记重新派生，相邻思考、工具分组和耗时行保留稳定引用；运行时错误、提问和排队消息随后单独组合，无关用量、上下文或后台进度不触发历史重建。同回合内相邻思考仅在展示层合并，保留首项 ID 和各段原文，不跨越工具或正文；相邻同名工具在展示层分组，保留各条原对象和顺序，提问保持独立；组内详情与计数共用后台状态解析，阅读位置记录到组首条。其他条目保持 `HistoryItem` 原对象，由组件直接读取类型、状态和内容。耗时与回合错误单独插入，停止和中断条目携带已记录的回合结束时间。计时依据回合自身状态；准备新回合或独立压缩不会让上一轮重新开始计时。组件通过原对象引用跳过未变化条目的重绘。

标题和正文实际改变展开状态前共用锚点保护通知，保存阅读位置并暂停贴底 400ms；拖选、链接与正文内控件不触发正文收起，也不发该通知。

主题与气泡变量写入后解析强调色，再经 Composer 明确传给水球画布，颜色更新不依赖无关状态渲染。翻滚时只构造一次原始粒子场，气泡湿区判断直接读取，水面由该场水平、垂直模糊生成。

读取任务时，已保存的正文、思考、摘要和工具结果优先于同 ID 的临时内容。临时内容只补未保存的条目，或更新尚无结果的工具进度；保存完成而完成事件尚未处理时，读取也不会退回旧内容。

历史图片读取失败属于请求材料错误，日志仍可写时保存真实失败原因；不把它归为日志写入失败。保存失败时，结束快照让当前页面里尚未结束的正文、思考和工具停止显示运行状态，保留临时内容并显示一次实际错误。它不补写历史或结束时间；重新读取仍以已保存的日志为准。准备失败不改变上一轮的结果。

创建任务在 RPC 结果里返回同一时刻的任务摘要、运行状态和该任务的事件序号，不扫描其他任务。首次发送只更新对应任务，不改变整个目录的序号；较早生成的目录更新仍生效，并保留读取开始后收到的新任务或新摘要。`SessionStore` 把摘要加入列表后打开会话，与选择已有任务共用读取入口。用户消息保存、任务改名和操作结束直接推送该任务的摘要，替换列表中的一行并按更新时间排序，不触发全目录读取。

读取任务期间暂存实时事件，按读取开始时的全局事件序号比较读取结果和事件，丢弃过时的响应；不能用发送事件时的序号替代读取开始时的序号。每次读取完整历史；切到空白页时作废未返回的读取并回放暂存的事件。读取失败时保留草稿和停止按钮，重试后恢复正文。阅读位置保存条目 ID 和偏移，临时输出借用相邻的已保存条目定位。

后台命令统一保存在前端的 `liveSessions` 中：读取任务时接收完整列表，之后只由后台命令事件更新；普通运行状态和操作结束快照不携带后台输出，也不扫描后台历史。未选中的任务只保留运行阶段、错误、后台命令，以及运行状态和摘要的事件序号，不缓存完整上下文、输入队列或用量。

模型读取、保存和删除直接返回脱敏目录及新序号；前端只更新模型列表。设置页的“重新读取”使用 `model.read`，只读取 `config.json`，不扫描会话日志。序号防止晚到的旧目录覆盖刚保存的配置。完整工作台读取只用于初始化、显式重读和项目或任务增删，不是局部操作成功的前提。

未提交的问答按任务和问题保存在 `SessionStore` 内存中，切换任务时保留，提交成功或后端确认问题结束后清除；刷新页面后需要重新填写。

文件标签统一目录末尾斜杠，以规范化的绝对路径为键，同一文件的相对路径、绝对路径和不同斜杠写法共用一个标签。

导航、输入候选、模型与项目选择、发送和复制等纯控件禁止选字，点击直接执行；正文内的链接、图表和可折叠内容检查拖选，防止复制文字时触发展开、收起或跳转。Skill 候选使用技能目录条目，输入前缀筛选本次目录；切换任务、项目、关闭技能输入或进入等待回答时作废未完成的读取结果；候选请求、显隐、键盘处理和 ARIA 共用同一启用条件。

任务菜单、模型、协议和气泡调色盘浮层共用原生 Popover 的显隐、层叠和关闭行为。CSS 根据触发按钮定位，随滚动和尺寸变化更新；组件只处理选择、焦点和方向键操作。调色盘的弹出和选中动画用 motion，和消息出现共用同一套弹簧。具体位置和间距见[工作台交互](desktop-ui.md#弹窗与浮层)。

## MCP

`McpManager` 按项目目录复用健康的连接；关闭 SDK 的工具目录缓存，每轮首次组装定义时直接查询服务器，查询失败不返回旧目录；取消发现时终止并等待本次服务器子任务收尾，再返回调用方。模型看到的工具定义来自本轮的实际目录，执行时在同一份目录里检查名称和参数。设置变化下一轮生效；服务器在运行中移除工具时，调用直接失败，不重试；HTTP 会话过期也不由 SDK 重新初始化并重放本次调用。发送和响应共用本地调用时限，停止或超时后的取消通知最多再等三秒；通知失败返回原因，保留共享连接，不打断同服务器的其他调用。

连接只为 MCP 管理页保留最近发现的工具名称和说明；完整工具定义交给本轮执行，包含参数格式的定义不随连接长期保留。

MCP 图片直接把 Base64 内容交给图片入口解码，按实际字节识别格式，与上传和文件读取共用图片检查与保存；不先拼成 data URL 再拆开。图片损坏时保留工具返回的文字，并将该工具结果标为错误。

列表读取、保存、开关和删除都一次返回完整配置、当前项目的已有连接状态和最近发现的工具，界面不逐个查询服务器。读取不会启动服务或查询远端；页面挂载时每次读取结束后等一秒再批量刷新，任务新建立的连接也会更新到页面；组件自己的忙碌状态暂停轮询并禁用保存、取消等操作，离页卸载时作废旧请求并停止计时。读取失败停止自动刷新并显示原因，可点击“重新读取”恢复；保存失败保留表单。只有失败状态显示“重试连接”，通过独立的 `mcp.reconnect` 重建当前项目的连接并发现工具，连接失败随服务器状态返回。

本地服务器放在 Windows Job Object 里，关闭句柄时终止整棵进程树，后端异常退出也会回收。

## 删除、移除与退出

删除任务先禁止该任务接受新操作，等执行结束后删除日志和附件；失败则恢复。删除成功后旧会话对象保持关闭，异步收尾不能重新启动它；草稿另行清理，读取草稿失败不阻止删除。

移除项目时，在应用生命周期锁内检查该项目的会话是否有执行、上下文预览、后台命令或待处理输入，有则拒绝；否则注销项目和已加载的会话，关闭该目录的 MCP 连接。会话文件保留，重新添加项目后按需打开。前端按当前任务列表清理对应草稿。

删除单个任务直接等待该会话停止：先取消并等待上下文预览、前台操作和压缩，再停止后台命令并等待完成。进程回收失败会阻止删除；进程已回收后的旧终态保存错误仍供输出和单独停止查询，但不再阻止删除日志与附件。应用退出时在退出入口并行停止所有会话，全部结束后再关闭 MCP 连接。Electron 完全退出最多等待十秒。

## 精简审查结论

| 对象 | 结论 | 依据 | 前提 |
| --- | --- | --- | --- |
| Skill 目录读取的取消标记与重试 | 保留 | 切换任务或项目时拒绝晚到结果；读取失败可重试 | 目录通过异步 RPC 读取 |
| 正文链接、图表和折叠内容的拖选保护 | 保留 | 选字复制和点击操作共存，需要区分拖选与激活 | 正文允许选字且提供点击操作 |
| 原生 Popover、Disclosure 和滑块保存队列 | 保留 | 分别负责浮层关闭与焦点、展开过渡、连续调档后的保存顺序 | 浮层、动效和连续拖动按现有交互运行 |
| 删除任务的关闭标记与 DeleteGuard | 保留 | 直接删除会让异步收尾重新启动旧任务；删除失败又需要恢复操作入口，guard 集中处理两种结果 | 删除仍需等待前台、预览和后台进程结束 |
| 模型配置的串行读改写与表单转换 | 保留 | 去锁会丢并发修改；共用表单和文件类型会混入未填写容量及密钥展示差异，另加缓存反而增加同步状态 | 单实例仍可并发处理 RPC，表单允许未完成输入 |
| Chat 与 Responses 独立编解码、共用传输与最终检查 | 保留 | 合并为通用状态机会增加协议分支；工具图片、内容顺序和私有续接字段确有不同 | 两种协议均为当前支持能力 |
| Responses 最终对象与失败片段分别保留 | 保留 | 只留终态会丢取消前已显示内容，只留增量不能恢复完整有序块与私有续接材料 | 成功保留续接，失败和停止保留已生成正文与思考 |
| SSE 跨块换行及首行 BOM 状态 | 保留 | 简单按双换行分割不能处理 CR、跨块 CRLF 和首行 BOM；这些是外部协议输入 | 仍直接解析提供方 SSE 字节流 |
| Bash 前台执行后按等待期限移交同一进程 | 保留 | 全部先登记后台虽能少一个等待分支，却让短命令多写开始和终态记录，还需额外抑制通知及改变列表呈现 | 短命令直接返回，长命令转后台且不重新执行 |
| 输出捕获中的 UTF-8 残字节、完整文件错误状态与回收错误分类 | 保留 | 删除会分别破坏跨块字符、把损坏输出文件当成功、或混淆阻止删除的进程回收错误与不阻止删除的旧保存错误 | Bash/MCP 分块输出，日志与进程回收可能独立失败 |
| 请求定义按轮加载与压缩复用 | 保留 | 每次请求重建会重复扫描技能和发现 MCP；跨轮缓存又需要失效机制；按轮保存恰好匹配生效规则 | 指令和工具在下一轮刷新，同轮工具循环及压缩复用 |
| 请求前的多个输入交付点及独立预算计算 | 保留 | 准备、压缩和超限恢复之间会收到新输入；只交付一次会推迟输入，缓存先前预算需额外失效规则 | 运行中允许追加输入，压缩会改变有效上下文 |
| 用户消息的局部公开投影 | 保留 | 为复用完整消息投影而额外克隆已移交保存的技能正文，或把展示职责塞进通用写入，收益不足；保存时间直接复用日志返回值 | 输入固定为一段文字加附件，尚无通用保存投影返回机制 |
| 提问等待槽、答案草稿及发送时的草稿身份 | 保留 | 后端问题用于校验与恢复等待；前端草稿用于切任务续填；发送期间继续编辑后不能无条件清空，单靠文本比较遗漏附件变化 | 切任务保留未交答案，刷新不恢复答案，发送期间可继续编辑 |
| 管理页局部异步生命周期与文件重读 | 保留 | 指令草稿、Skills 刷新、MCP 轮询和模型发现各有不同失效规则，泛化请求层会增加选项；永久文件缓存会显示旧内容 | 当前切换、刷新、错误保留和重新打开文件的交互保持不变 |
| Markdown、代码高亮和 Mermaid 按需渲染 | 保留 | 全量初始化增加启动工作，流式未完成图反复解析，渲染失败阻断原文均没有收益；现有原文回退保留阅读能力 | 保留流式正文、失败源码显示及按语言加载 |
| RPC 方法表与 TypeScript 依赖导出 | 保留 | 手写客户端契约增加第二份同一规则；递归去重与排序各有用途，无需新生成框架 | 前后端契约仍由 Rust 定义维护 |
